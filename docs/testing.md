# 测试与验收边界

## 自动检查

在项目根目录使用 **PowerShell**：

```powershell
npm ci --ignore-scripts --no-audit --no-fund
npm run validate
npm test
npm run build
```

| 入口 | 检查内容 |
| --- | --- |
| `npm run validate` | 全部源码 JSON；包格式、唯一 UUID、版本、互相依赖、最低引擎与脚本入口；语言文件与清单、中文键覆盖和英文占位符；JavaScript 语法、内部导入路径大小写及外部模块声明；文档本地文件链接 |
| `npm test` | 拒绝过期依赖版本、重复 UUID、错误入口、语言重复/缺失/占位符错误、错误导入；同步版本保留 UUID；两个 PowerShell 版本的归档、摘要与重复构建；失败保护已有产物及禁止写入源码 |
| `npm run build` | 重跑源码验证，打包仅包含 BP/RP，核对条目与必要文件，输出 SHA-256 |
| 发布工作流 | 对版本标签运行验证和测试；比较标签与提交；草稿和正式发布分别下载资产核对名称、字节数和 SHA-256 |

测试使用独立临时目录，含中文、空格和方括号，结束后仅清理对应临时目录。单元及构建测试不访问外部网络，不启动游戏，不写入世界数据。每个子进程设有超时。测试输出中的退出状态或失败断言是实际结果，预期现象不作为已通过的证据。

CI 在 `windows-latest` 对 Node.js 22、24、26 执行同一组命令，构建入口使用 PowerShell 7，回归测试同时运行 Windows PowerShell 5.1。CI 运行记录见 [Actions](https://github.com/xiangan666/Canopy/actions/workflows/ci.yml)。

## 游戏内手工验收

以下为待执行的验收步骤，不能从 Node.js 或 CI 结果推断已经完成：

1. 记录游戏完整版本、平台、两个包版本与实验选项，导入同一 Release 的两个包，在测试世界检查内容日志。
2. 使用简体中文输入 `./help`，确认中文帮助正常展示；切换英文后确认保留的上游语言仍可加载。
3. 检查带 `%1` / `%s` 的提示、帮助分页、规则菜单与 InfoDisplay，确认没有显示原始语言键、丢失参数或格式错位。
4. 在可丢弃世界中检查本次受影响的工具；升级后确认原有包引用仍生效，且没有 UUID 冲突或未知模块提示。
5. 涉及容器、实体、模拟玩家或世界状态的操作，确认权限、失败反馈和退出流程；保留异常时的内容日志。
6. 恢复备份验证回退路径。具体功能变更另补针对其正常、边界与失败路径的用例。

本轮工程整理不声称完成游戏内测试、全面 API 类型检查、全量游戏功能回归或性能优化。需要匹配 Beta API 的客户端或服务端后才能补齐运行验收。
